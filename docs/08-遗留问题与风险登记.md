## 一、当前未关闭

### C-25　强制出栏缺审批流（食品安全口径）

- **现象**：`POST /pen/{id}/slaughter` 带 `force=true` 可越过休药期硬校验，只需填 ≥10 字承诺说明。
- **为什么没按"加审批人"修**：该路由挂 `require_farmer`，admin/vet 没有农场上下文，`resolve_pen`
  取不到圈舍，技术上无法代农户操作。硬加角色门槛会得到一个永远走不通的分支。
- **当前缓解**：备注长度门槛 + `withdrawal_check="forced"` + `force_note` 原样进台账，事后可追溯。
- **关闭条件**：引入"兽医/监管方复核单"实体，强制出栏需挂一张已通过的复核单号。

### C-27　EMQX 侧未固化 ACL 与桥接配置

- **现象**：`docker-compose.yml` 起了 EMQX，但 broker 的认证/ACL 仍是默认配置，仓库里没有
  `emqx.conf` 或 bootstrap 规则；后端 `services/mqtt_bridge.py` 已实装订阅，但 broker 侧
  "谁能发布到哪个 topic"没有版本化。
- **影响**：换台机器 `docker compose up` 后，任何人只要连上 1883 就能往任意 topic 发数据；
  虽然入库前会校验 topic 与设备归属一致（伪造只会得到 topic-mismatch），但 broker 层应再收一道。
- **关闭条件**：`deploy/emqx/` 下补 `acl.conf`（设备只能 publish 自己的 `farm/{fid}/pen/{pid}/{sn}/data`，
  backend 只能 subscribe 该通配），并挂载进容器。

### C-28　视觉告警无真实来源，仅有演示注入

- **现象**：`POST /vision/simulate` 是手动触发的演示入口（有归属校验、走完整校验链、
  告警文案带「（模拟）」前缀），但平台内没有真实的边缘 AI 网关在推 `/vision/result`。
- **影响**：F09 的"识别扎堆/咳嗽/死亡"目前只能靠演示注入验证，不能证明真实链路。
- **关闭条件**：接一路边缘推理服务（YOLO/行为识别）按 07 协议第四节推 `/vision/result`。

## 三、口径说明（不是缺陷，是刻意选择）

- **业务错误统一 HTTP 200 + `{code,message,data}`**：前端 `apiFetch` 只认信封。代价是网关/监控
  看不到 5xx，需按 `code >= 50000` 自行统计。
- **LLM 诊断主导，规则正文兜底**：`diagnose` 在 LLM 失败时回退规则正文（EX-03）。"规则正文先行"
  的两段式已在 V0.4 改为 LLM 主导，`ai_analysis_text` 字段仅作旧 checkpoint 兼容保留。
- **`pen_unresolved` 先答后问**：圈舍没定位到时先按物种通用口径出结论、末尾追问，而不是阻塞诊断。
