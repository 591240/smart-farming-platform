# 智慧养殖多智能体平台 — 开发计划与里程碑

- 文档版本：V1.2
- 编制日期：2026-10-09
- 依据文档：PRD V1.7 第九章
- V1.2 变更（评审修复）：0.2/3.1 补 device_sn；4.1 补台账溯源外键；5.2 补圈舍定位规则；10.2/10.3 补药库校验与超时用例
- V1.1 变更：依据升级至 PRD V1.4；阶段 2.2 验收补转群用例；阶段 6.4 验收补 planned_kg 快照；变更表补评审修订记录
- **开发策略（按用户确认的方向）**：
  1. **猪先行**（湖南生猪主导产业，首发种子用户为养猪户）
  2. **前端骨架先行**：先把全部页面做出来（用模拟数据可点可看），再一个功能一个功能地往里填真实现
  3. 每个功能 = 前端页面接真后端 + 落库 + 独立验收，**随时保持系统完整可运行**

## 二、阶段任务分解

> 工期按 1 人投入估算（参考），可按实际人力折算。每个阶段完成后系统均可运行演示。

### 阶段 0：项目初始化 + 前端骨架（前端优先）

| 任务 | 产出 | 验收标准 |
|------|------|----------|
| 0.1 Docker Compose 环境搭建（PG/Redis/EMQX/Milvus/mediamtx） | docker-compose.yml 可一键启动 | `GET /health` 四项全绿 |
| 0.2 数据库建模与初始化脚本 | 按《02-数据库设计》建表（含 device_sn、台账溯源外键）+ 猪的物种/品种/参考价/兽药库种子数据 | init_data.py 跑完可查 |
| 0.3 后端项目骨架 | FastAPI 目录结构、JWT 鉴权中间件、统一响应/错误码 | swagger 可访问，鉴权依赖可复用 |
| 0.4 **前端全部 13 个页面静态骨架**（按《06-UI页面设计规范》浅白风格） | 引导向导/看板/场舍管理/喂食中心/繁殖管理/出栏/设备/告警中心/AI对话/待复核/台账/后台/个人中心 | 全部页面可导航跳转，数据用本地 mock，交互控件完整 |
| 0.5 前端 API 层封装 | 统一请求封装（鉴权头/错误码拦截/SSE 与 WS 客户端） | mock 切换真实 API 只改 base_url |

**里程碑 M0：前端全貌可演示**——给用户看 13 个页面长什么样，确认视觉方向后再填功能。

### 阶段 1：账户与首登引导（纵切第一刀）

| 任务 | 验收标准 |
|------|----------|
| 1.1 注册/登录接口 + bcrypt + JWT | 注册→登录→拿 token 调通任意接口 |
| 1.2 首登引导三步接口（主物种→养殖场→圈舍） | 引导完成标准：第 1、2 步完成即进看板 |
| 1.3 前端对接：登录页 + 引导向导页接真数据 | 新手机号注册后强制走引导；guide_done 后不再出现 |
| 1.4 个人中心：改主物种、改密码 | 改主物种后历史数据不变（EX-08） |

**里程碑 M1：能注册能登录，引导流畅走完。**

### 阶段 2：养殖场 / 圈舍 / 存栏管理

| 任务 | 验收标准 |
|------|----------|
| 2.1 farm/pen CRUD 接口（逻辑删除、多租户过滤） | 用户 A 看不到用户 B 的数据（40302） |
| 2.2 存栏变动事务（stock-change → 更新公母 → 落台账） | birth/sale 等五类变动正确累减；转群两笔联动正确（TC-P07）；负数拦截 40002 |
| 2.3 前端场舍管理页接真数据（含调整存栏弹窗） | 圈舍详情显示公/母数量实时正确 |

**里程碑 M2：场舍存栏账实一致。**

### 阶段 3：模拟传感器 + 环境告警闭环（演示核心）

| 任务 | 验收标准 |
|------|----------|
| 3.1 MQTT 消费者：写 sensor_data、Redis 最新值、防抖（连续 3 次超标） | 按《07-硬件通信协议》发送消息，消费者按 device_sn 回表校验归属，平台正确入库 |
| 3.2 离线判定（5 分钟无心跳 → device_offline 告警） | 模拟器停心跳 5 分钟后出现离线告警（EX-01） |
| 3.3 告警中心接口 + WebSocket 推送 | 超标 → 前端弹告警 ≤30 秒（模拟场景 ≤5 秒） |
| 3.4 告警状态闭环（pending→acknowledged→resolved） | 处理备注必填，落台账 |
| 3.5 模拟器 sensor_sim.py（频率可配、异常注入：超标/断心跳/乱序） | 注入超标数据 3 条内触发且仅触发 1 条告警（防抖+合并窗口） |
| 3.6 前端：设备管理页、看板传感器曲线接真数据 | 曲线来自 sensor_data 真实历史 |

**里程碑 M3：模拟数据跑通报警全链路**——这是整个平台的"心跳"，后续 Agent 都吃这条链路的数据。

### 阶段 4：台账落库与导出

| 任务 | 验收标准 |
|------|----------|
| 4.1 台账服务统一写入（前面阶段的落台账点补齐，含 alert_id/lifecycle_event_id/medicine_usage_id 溯源外键） | 告警、存栏变动均有台账记录且可回溯来源，完整性 100% 可自动核验 |
| 4.2 台账查询接口（多条件筛选分页） | 筛选正确 |
| 4.3 Excel 导出（动态扩展列按 variety.record_ext_fields） | 猪场导出列序正确 |
| 4.4 前端台账页接真数据 + 导出按钮 | 下载文件可打开 |

**里程碑 M4：台账档案可信可导。**

### 阶段 5：AI 问诊链路（Agent 核心）

| 任务 | 验收标准 |
|------|----------|
| 5.1 Milvus 集合搭建 + 猪病知识库整理入库（含溯源字段） | 检索结果带来源 |
| 5.2 LangGraph 主图：意图识别→加载上下文与知识检索（品种路由+上下文+RAG 合并一步）→诊断 | 意图分类准确；圈舍定位规则（pen_id/单圈舍自动/槽位抽取/反问）正确；检索无结果时明确拒绝（EX-04） |
| 5.3 用药节点：兽药库校验 + 违禁拦截 + 休药期强制输出 | 推荐药必在库内；瘦肉精类被拦截 |
| 5.4 饲料建议节点（本阶段先出营养建议，配方大脑在阶段 6） | 附依据来源 |
| 5.5 SSE 流式输出 + 会话历史持久化 | 首字 ≤3s，全流程 ≤60s；会话可回看 |
| 5.6 免责声明常驻（结果页/高危弹窗/用药结尾） | 三处齐全 |
| 5.7 前端 AI 对话页接真后端 | 多轮对话、流式渲染 |

**里程碑 M5：问诊闭环可用**——症状进、诊断+用药+饲料建议出。

### 阶段 6：喂食中心（配方大脑三大支柱）

| 任务 | 验收标准 |
|------|----------|
| 6.1 饲养营养知识库入库（doc_type=nutrition） | 配方建议可溯源 |
| 6.2 配方大脑接口（生成/替代方案/成本核算） | 输出原料比例+顿数+每顿喂量+成本；缺料时给 2~3 套替代+对比表 |
| 6.3 配方生效与台账联动；原料价格管理（改价重算、>30 天提示） | EX-16 不达标红字；EX-17 价格时效提示 |
| 6.4 饲喂日历（计划 vs 实际、批量登记、一键打卡、>3 倍确认） | EX-14 拦截生效；planned_kg 快照保证历史对照稳定 |
| 6.5 称重记录→日增重 vs 标准、采食曲线、降 15% 异常提示 | EX-15 下降确认生效；三联动归因出提示 |
| 6.6 前端喂食中心页接真数据（配方卡片/日历/两条曲线） | 页面全部图表有真实数据 |

**里程碑 M6：喂食闭环跑通**——配方→执行→曲线→异常归因。

### 阶段 7：全生命周期管理 + 出栏休药期

| 任务 | 验收标准 |
|------|----------|
| 7.1 母畜档案 CRUD + 状态机事件驱动 | 非法跳变 40003（EX-12） |
| 7.2 预产期自动计算 + 提醒（前 3 天看板+告警中心） | 配种后 due_date 正确；提醒按时出现；过期未分娩持续置顶（EX-13） |
| 7.3 断奶/免疫提醒生成 | 提醒列表可处理 |
| 7.4 出栏登记 + 休药期硬校验 + 强制继续留痕 | 未满拦截展示三要素；force 留痕落台账 |
| 7.5 前端繁殖管理页、出栏登记页接真数据 | 档案时间线正确展示 |

**里程碑 M7：繁殖到出栏全周期管控可用（含合规硬校验）。**
