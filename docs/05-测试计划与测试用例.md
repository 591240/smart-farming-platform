# 智慧养殖多智能体平台 — 测试计划与测试用例

- 文档版本：V1.3
- 依据文档：PRD V1.7、《01-系统架构设计》《03-API接口设计》《07-硬件通信协议》
- V1.3 变更（F09 实施回写，承接《17-功能PRD-F09》文档同步项③）：2.5 节补 TC-V01~V06（分级三态含 death≥0.5→high 已采纳/去重/健壮性/合并升级/免责三处逐字一致/端到端延迟）
- V1.2 变更（评审修复）：新增 TC-G16/G17（HITL 24h/48h 超时）；TC-L04 存栏归属口径修正；TC-F13 计划量实时计算口径修正

- 测试范围：V1.0 全部功能（猪先行范围）+ 非功能指标

## 一、测试策略与环境

### 1.1 测试分层

| 层级 | 工具/方法 | 覆盖 |
|------|-----------|------|
| 单元测试 | pytest | service 层校验逻辑（存栏/休药期/状态机/配方成本） |
| 接口测试 | Postman / pytest+httpx | 全部 API（03 文档逐条） |
| Agent 链路测试 | 模拟器 + 真实 LLM（低温度） | 意图识别、RAG、诊断分级、工具白名单 |
| 集成/告警链路 | sensor_sim / vision_sim 异常注入 | 防抖、离线、合并窗口、WebSocket |
| 性能测试 | JMeter / Locust | 非功能指标（第六节） |
| 演示验收 | 3 天养殖故事脚本 | PRD 1.4 成功指标 |

### 1.2 测试环境

- Docker Compose 本地环境（架构文档 7.1）；数据全部来自模拟器
- LLM 用测试 Key（独立额度）；气象 API 用免费额度 + 断网注入测降级

### 1.3 准入/准出

- 准入：开发自测通过、接口文档与实现一致、模拟器可用
- 准出：Must 用例 100% 通过、高优先级缺陷清零、性能指标达标、PRD 成功指标 5 项全过

## 四、模拟器异常注入矩阵

| 注入项 | 模拟器操作 | 验证点 |
|--------|-----------|--------|
| 瞬时抖动 | 单条超标后恢复正常 | 不告警（防抖） |
| 持续超标 | 连续超标 | 1 条告警+合并窗口 |
| 心跳中断 | 停发心跳 | 5 分钟后离线告警 |
| 乱序数据 | 时间戳倒序发送 | 入库按 collect_time 排序，曲线不乱 |
| 非法 payload | 缺字段/类型错 | 消费者跳过并记日志，不崩溃 |
| 重复上报 | 同消息重发（QoS1 场景） | 不产生重复告警 |

## 五、缺陷管理与优先级

| 级别 | 定义 | 处理要求 |
|------|------|----------|
| P0 | 资损/合规/数据错误（休药期校验失效、存栏错账、越权） | 阻塞发布，立即修 |
| P1 | 主流程阻断（登录失败、告警不出、问诊 500） | 发布前清零 |
| P2 | 非主流程异常、体验问题 | 排期修复 |
| P3 | 文案、样式微调 | 记录待办 |

**回归范围**：每次修复 P0/P1 后回归其所属模块 + 合规用例（TC-L06~L09、TC-G07~G08 永远全量回归）。
